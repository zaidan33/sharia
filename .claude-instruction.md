# IMPLEMENTASI PRD — Analytical Engine & Web App Kelayakan Pembiayaan

Baca dulu kedua dokumen referensi ini:
- `docs/PRD.md` — spesifikasi produk lengkap
- `docs/IMPLEMENTATION_PLAN.md` — panduan implementasi teknis

## ATURAN DASAR (binding)

1. Modul di `/lib/engine/` adalah **fungsi murni**. Tidak mengimpor `db`, tidak memanggil `fetch`, tidak membaca `process.env`.
2. Uang = `bigint` di DB dan `number` bilangan bulat rupiah di engine. Tidak ada float.
3. Tidak ada `NaN` atau `Infinity` yang keluar dari engine. Nilai tak terdefinisi = `null`.
4. Setiap Server Action memverifikasi sesi dan kepemilikan baris.
5. Jangan ubah file boilerplate di luar yang diperlukan (auth, layout, font).
6. Jangan gunakan em dash (—) di UI. Gunakan tanda hubung biasa (-).

## URUTAN IMPLEMENTASI (8 Fase, sesuai Bagian 12)

### FASE 0 — Setup awal
- Matikan pendaftaran publik di `lib/auth.ts` (`disableSignUp: true`)
- Setup font Poppins, Inter, JetBrains Mono via `next/font/google` di `app/layout.tsx`
- Update `app/globals.css` dengan token warna dari PRD §12 dan IMPLEMENTATION_PLAN §10
- Pastikan `npm run dev` berjalan tanpa error

### FASE 1 — Skema DB
- Buat `db/schema/scenarios.ts` dan `db/schema/scenario-results.ts` (sesuai Implementation Plan §4)
- Buat index `db/schema/index.ts`
- Jalankan `npm run db:push`
- Pastikan foreign key ke tabel `user` (dari boilerplate Better Auth) berfungsi

### FASE 2 — Engine + Test
Buat file di `/lib/engine/`:
1. `rate-conversion.ts` — konversi tingkat, EAR dari jadwal
2. `financing-cost.ts` — jadwal pembiayaan untuk 4 skema
3. `cashflow.ts` — proyeksi arus kas dengan varian base/best/worst
4. `ratios.ts` — DSCR, DER, ROI, BEP
5. `valuation.ts` — NPV (Newton-Raphson + bisection), IRR
6. `index.ts` — `computeScenario()` orkestrasi

Tulis test dulu (`__tests__/`) menggunakan vektor acuan dari §7.1 dan §7.2.
**Fase ini selesai ketika `npm test` hijau — belum ada UI.**

### FASE 3 — Validasi + Server Actions
- `lib/validation/scenario-schema.ts` — Zod schema (Implementation Plan §5)
- `lib/actions/scenario-actions.ts` — 6 Server Actions (Implementation Plan §8)

### FASE 4 — Dashboard & Form
- `/dashboard` — daftar skenario + ringkasan (Implementation Plan §9.2)
- `/scenarios/new` — form 4 langkah (PRD §7)
- `/scenarios/[id]/edit` — ubah skenario
- Semua state: loading.tsx, empty-state, error.tsx, not-found.tsx

### FASE 5 — Halaman Detail
- `/scenarios/[id]` — kartu metrik, formula-panel, tab varian, grafik arus kas (Recharts), grafik DSCR, tabel, slider discount rate, panel batasan model

### FASE 6 — Seed Data
- `db/seed.ts` — 20 kasus seed (Implementation Plan §11)
- Jalankan `npm run db:seed`
- `golden-seed.test.ts` — cocokkan 20 baris tabel §7.3

### FASE 7 — Landing Page
- Hero dengan elemen signature perbandingan syariah vs konvensional (angka dari §2)
- Problem section, cara kerja, prinsip transparansi, CTA
- Komponen di `/components/landing/`

### FASE 8 — QA
- Responsif 1440/1024/768
- Lighthouse Accessibility ≥ 95
- Tidak ada NaN/Infinity bocor ke UI
- Warna/font sesuai PRD §12
